Large language models can now write simulation programs of operational processes and workflows. These programs can be reused to answer what-if questions on new records and policies. However, incorrect answers can still be provided to what-if questions by a program that reproduces recorded history. Such programs can fail in three ways: by applying a wrong change to records, or by applying changes to records other than the ones the question is about, or no longer be valid once their policies are revised. Current checks return pass-or-fail verdict for the whole program, which conveys little information about any single answer's trustworthiness.

We propose \textbf{Vouch}, a library that judges whether an answer from a generated simulator can be trusted for the change being asked about. Each what-if question is turned into a structured change which is checked against the program and the current records. The library also keeps a record of the kinds of change each program has passed or failed, and repeats the relevant tests whenever the program is reused. We apply it to three program-generation platforms, with programs built by five language models, across four domains: manufacturing, IT operations, and pharmacy and loan application workflows, using independently checked reference answers. We compare it with the platforms' own checks where they exist, an LLM-as-a-judge, and a ReAct agent that can run the program. We measure how many correct answers are kept, how many wrong answers are accepted, how many correct answers are wrongly rejected, and what the checking costs.
