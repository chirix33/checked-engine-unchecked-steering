\section{Limitations and Threats to Validity}
\label{sec:limits}

\paragraph{Known blind spots.} We searched for wrong programs that the library would still trust by planting specific confusions into otherwise correct programs on development data, and added checks for most of them. Two remain and we report them as limits. In workflows, when the unavailable workers would have been busy during the interval, a program that makes the workers of another pool unavailable, or one worker more than asked, can pass the resource tests. In IT, a program that \emph{adds} to a task's priority instead of \emph{setting} it can pass. After the first switched decision, the routing test checks routes, case ends and paths but not timing, so a program with right paths and wrong times after a switch relies on the other tests to be caught. The \cfg{Generic} and \cfg{Program-wide} baselines keep an IT CPU/memory blind spot that \gate resolves.

\paragraph{Design on development data.} Several parts of the library were added or fixed after seeing development results: the record-comparison routing test and its no-switch check, the reuse rules, the blind-spot checks, and the IT record mapping for \otf. None used test labels or any system's test answers, and the main test run happened once after a hashed freeze. Two checks on the test documents were run with the reference simulator as the program, to confirm the tests never reject a correct program; they changed nothing. Development results favor the library and are not reported as evidence.

\paragraph{The reference and the builders share a model family.} Claude models wrote the workflow semantics, the reference engine and the hand-worked cases, and a Claude model wrote the independent checker. Claude models also built and judged programs. A misreading of the semantics shared by the reference and Claude-built programs would be invisible to our scoring. Separately started agents reproduced sampled runs from the document text alone, and blind manual checks agree, but these reduce rather than remove the risk. Some semantic choices are conventions (for example, which workers a partial unavailability removes, which the questions now name), and answers depend on them.

\paragraph{Scope.} Workflow runs are deterministic realizations of two published synthetic models under our written semantics; they are not real organizations, and all random draws are printed in the document, which real operations do not know in advance. Manufacturing and IT outcomes are simulated under written policies. We study four domains, three platforms and 86 judged programs; builds of one model on one document are not independent, so per-program results matter more than pooled rates. Ollama-built programs exist only for \otf, the Qwen cohort has three programs, and model-based judges ran on subsets. The library needs an adapter per platform and a process description per domain; the stated-rule checks apply only where programs print records that name tasks, waits and workers, which \otf's free-form records do not.

\paragraph{Sandbox and cost accounting.} Generated code ran in a sandbox that was hardened during the project after reviews found escape routes; development runs before the hardening used the earlier form, and a scan found no generated program that reached outside it. Program executions inside the ReAct sandbox are counted from a log written inside it, a lower bound. One platform's build costs were estimated from its own token log rather than our ledger.

\paragraph{Broader impact.} The aim is fewer wrong answers presented as computed facts. A gate that says \Trusted can still be wrong: it reports that specific tests passed, not that the answer is correct, and users should read its decline reasons as evidence about what was and was not tested.
