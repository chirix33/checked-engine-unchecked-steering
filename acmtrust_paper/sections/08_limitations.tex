\section{Limitations}
\label{sec:limits}

\paragraph{Blind spots.} We looked for wrong programs that Vouch would still trust by planting specific mistakes into otherwise correct programs, and added checks for most of them. Three planted mistakes still pass. In the workflows, when the unavailable workers would have been busy anyway, a program that makes workers of another pool unavailable, or one worker more than asked, can pass the worker tests; in IT, a program that \emph{adds} to a task's priority instead of \emph{setting} it can pass. The stated-rule checks need records that name tasks, waits and workers, which \otf's free-form records lack.

\paragraph{Development and test data.} Vouch was designed on development data. Three decisions used test questions, though no real program's test answers. A planted program that mixed up CPU and memory requests had five wrong answers trusted on test questions, which prompted the IT check that separates the two; the fix was designed on development data and run once on test. The stated-rule checks were likewise designed on development data and run once on test with planted programs scored against reference answers. The rule that an answer counts only if it is trusted and produced was chosen with test-side counts in view, and the reference programs were run through Vouch's tests on test documents to confirm that the tests never reject a correct program. None of these runs led to a change of tests, thresholds or prompts, and the main test run happened once, after the freeze.

\paragraph{What the study does not show.} No policy document shares a fingerprint with a test document, so we make no claim about transferring recorded results across policies. We did not compare against retesting every question, so the record's effect on accuracy is not measured. Generic tests lack Vouch's routing, worker and stated-rule checks, so their gap to Vouch reflects the whole choice of tests. The samples are small and dependent: several builds share a model and a document, the workflow test questions come from \rRunsWf{} runs, and most wrong answers come from one platform and two families. Resampling whole runs kept every headline result, but the intervals describe these programs and questions only.

\paragraph{The reference and the builders share a model family.} Claude models helped write the workflow semantics, the reference engine and the hand-worked cases, a separately started Claude model wrote the independent checker, and Claude models built and judged programs. A misreading of the semantics shared by the reference and the Claude-built programs would be invisible to our scoring; independent reproductions from the document text reduce this risk but do not exclude it.

\paragraph{Scope.} The workflow runs are fixed realizations of two published synthetic models, with every random draw printed, which real operations would not know in advance. Questions come from templates and are easier to interpret than questions written by people. Open-weight programs exist only for \otf, and LLM judges ran on subsets. Vouch needs an adapter per platform and code that reads each domain's documents, while LLM judges receive the document itself. Program runs inside the ReAct sandbox are counted from a log written inside it, a lower bound, and \devs build costs are estimated from its own token log. Finally, \Trusted means only that specific tests passed.
